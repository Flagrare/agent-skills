# Career skills glossary

The career skills (`/flagrare:promotion`, `/flagrare:impact-scan`, `/flagrare:opportunity-scan`, `/flagrare:career`) and the Career Board use the plain names below in anything the user reads: digests, summaries, the promotion map's markdown, the board. The technical names stay in file shapes, script output and code.

Clarity comes first, and the user still learns the terms their company uses. The first time a term appears in a digest or summary, give its plain meaning in a few words, and add the company's own word in parentheses when the user will hear it at work (for example "your written case (the promotion packet)"). After that, use the plain name.

| Say this | Not this | What it means |
|---|---|---|
| Senior behaviors (or "<target level> behaviors") | rubric rows | The behaviors on the company's ladder for the level the user is going for. Each one is a line managers rate against. |
| Senior behaviors not shown yet | open rubric rows | Behaviors the promotion map marks partial or not started. |
| Proof | evidence | Something the user did that shows a behavior, with a link. Every logged contribution counts as proof. |
| Behaviors with little proof | rows with thin evidence | Behaviors with fewer than 3 pieces of proof. |
| Your written case | packet | The document the manager takes into the promotion decision. |
| How your written case would read today | packet readiness | Each section of that document rated strong, some proof, or no proof yet. |
| Strong / some proof / no proof yet | strong / thin / empty | Packet section states. |
| Promotion committee | calibration | The meeting where managers and directors review promotion cases together. |
| The project you own | initiative, active initiative | One piece of work the user owns end to end, agreed with their manager. |
| Proposed projects | candidates, proposals | Problems a scan found that the user could own. Nothing is theirs until they keep one and their manager agrees. |
| Lots of answering, nothing owned | balance warning | Many contributions in the last 30 days and no project the user owns. |
| Check first | verify first | The one check that makes a draft safe to send. |
| Promotion map | map | The sourced document `/flagrare:promotion` keeps: target, process, calendar, the behaviors, people, the written case. |
| People who haven't seen your work yet | unseen people | People in the decision who have no first-hand context on the user's work. |
| Your lever | user_lever, lever | What in the user's own work moves a metric (the systems they own, the screens they build). A metric with no lever in their seat belongs to another team. |
| Company priorities | priorities | The themes and metrics leadership watches, each with its owner team. |
| Recognition | bonuses | Thanks peers gave the user in the company's recognition tool. Proof someone saw the work, and a source of peer-feedback picks. |
| Ranking score, "15 of 18" | score, rank, weights | How a proposed project ranks: 0 to 2 on eight questions, with moving a company metric counting double. Zero on that one makes it a fix, not a project. |
| The bet | hypothesis | "We believe X will Y because Z": what a proposed project expects to change, set before building. |

Row ids (`scope.proactive-discovery`), file names and statuses like `handed_off` are code: they belong in item blocks, logs and files, never in a table cell or a sentence written for the user. Each behavior's plain name is its `label` in the promotion map.
